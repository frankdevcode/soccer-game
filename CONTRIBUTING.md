# Contributing to Soccer-Game

Thank you for your interest in contributing to Soccer-Game! This document provides guidelines and instructions for contributing.

## Code of Conduct

- Treat all contributors with respect
- Provide constructive feedback
- Follow project standards
- Write clear, professional code

## Getting Started

1. **Fork the repository**
2. **Clone your fork** locally
3. **Create a feature branch** (`git checkout -b feature/your-feature`)
4. **Follow** [DEVELOPMENT_STANDARDS.md](DEVELOPMENT_STANDARDS.md)
5. **Submit a Pull Request**

## Pull Request Process

1. Update documentation as needed
2. Add tests for new functionality
3. Ensure all tests pass
4. Update CHANGELOG.md
5. Request review from maintainers

## Commit Message Format

```
[CATEGORY] Brief description

Detailed explanation of changes
- Bullet point 1
- Bullet point 2

Fixes #issue_number
```

### Categories
- `[FEAT]` - New feature
- `[FIX]` - Bug fix
- `[REFACTOR]` - Code refactoring
- `[PERF]` - Performance improvement
- `[DOCS]` - Documentation
- `[TEST]` - Test updates
- `[STYLE]` - Code style
- `[INIT]` - Initialization
- `[CLEAN]` - Cleanup

## Development Standards

Please ensure your code:
- Follows C++ naming conventions (Unreal Engine 5 style)
- Is properly commented in English
- Includes unit tests
- Passes all existing tests
- Has good performance
- Is well-documented

See [DEVELOPMENT_STANDARDS.md](DEVELOPMENT_STANDARDS.md) for complete details.

## Reporting Bugs

When reporting bugs, include:
- **Description**: Clear explanation
- **Steps to Reproduce**: Exact steps
- **Expected Behavior**: What should happen
- **Actual Behavior**: What actually happens
- **Environment**: OS, Engine version, etc.
- **Screenshots**: If applicable

## Requesting Features

Feature requests should include:
- **Description**: Clear explanation of the feature
- **Motivation**: Why is this needed?
- **Use Cases**: How would it be used?
- **Implementation Ideas**: Optional suggestions
